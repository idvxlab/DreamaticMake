# 电源与备用预算 v0.1

输入：需求 v0.3，用户明确“断电继续工作、体积优先、不限定时长”。输出为设计预算，不是额定功耗或实测续航。

布局更新：当前元件选型为v0.2，RTC VIN仍接3.3V，VBAT改接主保护电池，纽扣电池座为空；此备份支路没有改变主电池耗尽后需校时的边界。以下预算仍为未实测假设。

## 电源路径

```text
外部 USB 5V → Feather 板载 USB-C / 充电及电源切换
保护 1S LiPo 400mAh ↔ Feather 板载 JST-PH / 充电路径
                      ↓ 板载 3.3V 稳压轨
                  主控 + OLED + RTC
                  GPIO / 电阻网络 → 压电器
```

显示与 RTC 不接 USB VBUS；后者只在插电时存在。不要把外部 5V、电池正极与 3.3V 直接并联。板载自动选择和充电属于电路本体，项目原生契约没有模拟其瞬态或电池电化学。[官方电源路径说明](https://learn.adafruit.com/adafruit-feather-rp2040-pico/power-management)

外部 USB 输入暂按 5V、至少 1A 的接口条件选取，采购产品与电缆型号未锁定。Feather JST-PH 与所选原装电池极性匹配；任意同外形替换电池不能默认匹配。电池最大允许充电电流按 400mA 核对；板载充电设定需结合实际板版本与 RPROG 核验，不在未知情况下写成已确认的 100mA 或 500mA。

## 3.3V 轨初步分配

| 负载 | 设计分配 mA | 状态 |
| --- | --- | --- |
| Feather 主控与板载开销 | 30 | 假设；工作频率、软件运行时与指示灯会改变耗电 |
| OLED 时钟画面 | 80 | 预算上限目标；不是厂家最大额定，需测全白及实际画面 |
| RTC 整板 | 2 | 假设；包含板载 LED 与上拉，不能只使用芯片低功耗值 |
| 压电/输入及余量 | 8 | 初步预留，不代表已测负载 |
| 合计 | 120 | 设计预算，实际超出时重新选型或调整电路 |

Feather 的 500mA 是峰值，不能据此认定可持续输出。以 5V→3.3V、120mA 估算，仅稳压器压差损耗约 0.204W；充电损耗和壳内散热还未计入，不能从此数值断言温升合格。OLED 厚度、电流未知项不因预算表而变成已知额定。

## 续航敏感性

电池名义电量 400mAh。用 **70% 可用容量**作为保守设计假设，把温度、老化、稳压掉压与截止等综合折减；这不是对电池的测试或厂家保证。按电池端实测平均电流计算：

`t_h ≈ 400mAh × 0.70 / I_battery_mA`

| 假设电池端平均电流 mA | 粗算 h |
| --- | --- |
| 50 | 5.6 |
| 80 | 3.5 |
| 120 | 2.3 |

这些点仅说明电流对时长的影响，不能把 3.3V 轨电流直接当成完整的电池电流。名义能量按 0.4Ah×3.7V 为 **1.48Wh**；3898 产品正文另写约 1.9Wh，与容量/电压不一致，本项目不用该能量描述。[产品规格](https://www.adafruit.com/product/3898)

## 后续必须执行的检查

1. 收货后核对电池极性、保护板、接线与充电电流设定；检查实际模块电流及连接器规格。
2. 全亮、夜间、响铃、设置四种模式测电池端及 3.3V 电流，包含运行时和指示灯消耗。
3. 分别在显示、响铃和贪睡状态拔插 USB，记录 3.3V 最低电压、是否复位、显示是否消失、是否漏响或丢失倒计时。
4. 满充后在规定画面、亮度、温度与响铃频次下持续运行到停止，记录真实续航；再测试低电量时的切换和响铃。
5. 测充电＋显示＋响铃同时发生时的壳内温升、满充终止和电池剩余电量稳定性。板载充电和自动切换说明不等于完整系统的充电验收。
6. 本基线无第二枚 RTC 电池；主电池耗尽后检查 RTC 时间有效性，必要时要求校时；不恢复旧贪睡或按无效时间触发。

当前全部为待执行计划。若音量、温升或续航不满足实际使用，再修改电池、屏幕或驱动及其原生版本。
