# Agent Workbench

此入口按“不读取现有业务代码”要求独立新增，未替换原有业务运行时。只调整项目脚本与 Vite 多入口构建配置。

当前截图、测试范围和已知限制以[轻量检查点](checkpoints/2026-10-29/README.md)为准。下方保留接入过程说明。

## 启动

```sh
npm ci
npm run build
npm run workbench
```

打开终端中的带令牌本地链接。服务默认监听 `127.0.0.1:4322`，固定使用 Pi SDK **1.3.0**。

### 自定义网关与分角色模型

点击右上角「模型设置」，默认 API 地址为用户指定的 `https://apicz.boyuerichdata.com/v1`：

1. 在本机页面填写该网关的 API Key，点击「获取可用模型」。查询只发送到该地址，不跟随跨站重定向。
2. 结构/CAD选择网关实际提供的 Kimi ID。列表中存在明确的 `kimi-k3.1-pro` 或 `k3.1-pro` 时优先识别；别名不同则手动选择，不猜测不存在的型号。
3. 产品经理、调研、嵌入式、外观、软件、审查六类选择 `deepseek-flash` 或网关实际提供的 Flash ID。
4. 点击「保存配置」。保存前再次核实两个 ID 都在当前 Key 的模型列表内。

配置保存到忽略的 `workspace/workbench/connection.json`，权限0600。查询接口只返回 `hasKey`，不会回传密钥；保存成功即清空输入框。Key不进入项目导出、调用协议或上下文。若 API 地址改变，必须明确填写新Key，不把原Key自动转发到另一地址。

每次真实调用用 Pi 的 `ModelRuntime` 注册 `workbench-gateway`，显式传入所选 model 与runtime credential；不会回退到官方URL、SDK默认模型或其他角色的模型。结构使用Kimi低档推理（保持推理开启）、6分钟调用时限，其余角色显式发送关闭思考参数、3分钟时限。DeepSeek使用JSON输出模式，Kimi根据实测禁用developer消息角色，改用system。当前协议为 OpenAI Chat Completions兼容接口，该网关以上两个模型已完成真实提案链路试跑，其他平台仍需实测。SDK本地预算64K上下文/16K输出是请求限制，不代表供应商宣称的模型规格；未展示费用估计。

不加载`.env`，不要求在聊天里发送Key，也不读取原应用的模型配置。保存后可在下方输入“继续”，由产品经理重新评估并续跑已保留项目。

## 产品经理持续统筹

空画布不预设七个专家或工作流。实际执行为：

1. 用户提交需求；产品经理作为首次调用接收需求，委派调研团队。
2. 调研团队返回问题卡片；用户在左侧工作区选择并通过认证接口提交。
3. 产品经理读取选择、现有结果和失败信息，决定下一轮1-3项任务。
4. 专家返回后，产品经理在需要时再次被调用；分析师提出的有界workflow-plan可由后台按成功依赖接续，每批最多3项任务。产品经理决定追加分析、拆分功能、比较候选、外观设计、结构工作、必要的软件、审查、返工或暂停。
5. 任意补充反馈都交回产品经理，而非由界面绕过产品经理直接调用某专家。

每次调用产生独立节点。没有假定的七步顺序，也不一次性生成完整计划。`dispatch` 只描述下一批已经具备输入的任务，`dependsOn` 引用已有成功专家调用的 invocation ID。结构必须依赖硬件与外观结果，软件必须依赖结构。每批最多三个任务并行。

审查只是建议，不具有自动批准/否决权。专家失败也会作为观察交回产品经理，由产品经理决定重试、改派或暂停。`blocked` 如实标识必要能力缺口；`finish` 仅代表产品经理声明的本轮交付范围完成，不意味着编译、制造或CAD验证成功。自动循环有20轮及80节点上限，达到后暂停等待调整。

产品经理按风险合并安排关键阶段的审查，通常0–2次，不为每个功能块配审查者；审查失败最多重试一次，用户明确追加审查时除外。这是调度指导，实际调用及失败仍逐条记录。画布默认“主要依赖”：保留专家的数据依赖与虚线委派，隐藏产品经理读取历史的观察连线，并省略已由其他输入传递的冗余依赖。可切换“全部连线”，调用详情和原协议输入始终完整保留。

最终响应先校验JSON、角色格式、引用和几何约束，失败时在同一Pi会话内至多修复一次，并记录`protocolRepairs`；两次仍不合法则如实失败。真实硬件证据独立于专家最终输出保存，失败调用取得的证据也传给产品经理。`toolActivity`记录实际工具执行、检索词和命中数；嵌入式没有既有证据又没执行检索时，不能仅用文字声称“全库无记录”。调用详情可查看这些记录。

## 左侧工作内容

默认跟随当前阶段，点击右侧节点、选择历史调用或切换类别可回看对应结果；“跟随最新进度”恢复自动跟随。

- 产品经理：当前决策依据、下一批委派、总结或阻塞原因。
- 调研团队：可操作的问题卡片、用户已选记录与需求分析。
- 嵌入式团队：硬件候选、元件、供电、接口和取舍对比。
- 外观设计师：效果图与前/顶/侧视图；图片引用与待生成规范分别标识。
- 结构工程师：此时才挂载3D预览，支持旋转、三视图、分解和尺寸包络。
- 软件工程师：程序、固件、I/O和执行逻辑。
- 审查者：独立建议与风险说明。

实际图像已支持通过模型设置中的专用生图模型生成：外观角色先输出image-request，产品经理再委派外观角色调用generate_product_images执行1–4个视图。图片保存到本机并以真实执行证据进入节点；未配置、失败或待生成请求仍明确标记。图片仅是概念视觉参考，不是工程图。3D可显示设计包络和通过本地STEP检查绑定的真实硬件网格；单件读取不代表整机CAD或装配已验证。

## 协议与认证

所有工程包沿用 `dreamatic.workbench/1`。单个汇聚输入、单个数据包输出；内部固定 `structure`、`motion`、`circuit_energy`、`flow`、`logic` 五类，不按具体元件扩张端口。

每个包带 `id`、`invocationId`、输入包引用、摘要与证据等级。初始需求、问题卡片、历次选择、用户反馈、产品经理决策同样以包保存；下游得到必要的祖先输入。条目采用 `{id,kind,label,properties,references}`，引用必须可解析。几何、BOM和固件共用此版本约定。

问题卡片随调研调用保存，选择记录追加保留而非覆盖前轮。产品经理 `decision` 作为 `logic` 条目保存；已派发任务仅保留为历史记录，不能作为未来固定工作流。

认证采用本机访问令牌交换 HttpOnly、SameSite=Strict Cookie。认证种子保存在忽略的 `workspace/workbench/auth.json`（权限0600），启动时复用，服务重启后同一浏览器仍可登录。Cookie有效期一年，最后30天使用时自动续期；清除浏览器Cookie、换浏览器或删除本机认证文件后需要重新连接。删除认证文件并重启服务可撤销所有既有登录。认证文件独立于项目导出和模型Key。选择和调整均需认证、同源及显式JSON请求；无 agent 审批工具。

连接检查、首次登录和连接中断使用独立界面，项目未加载时调用数显示“—”，不会显示成零调用的空项目。服务暂时停止时，恢复后点击“重试连接”即可继续读取项目。

## 验证与当前能力边界

`npm run check`、`npm test`、`npm run build`；`npm run test:workbench:ui` 使用隔离测试调用器和本机 Chrome，验证空画布、产品经理逐轮调度、问题卡片、不同类型预览、仅结构使用3D及反馈回到产品经理。

已完成真实外部模型提案链路验证，见2026-10-27 实跑记录（本地历史记录，未随轻量检查点上传）。此前记录未连接硬件库，不能作为真实选型依据。现在新增[真实硬件库接入](workbench-hardware-library.md)，七个角色可检索资料并检查单件STEP，使用版本化引用共享参数、原文件与包络。已连接专用生图工具，实际Seedream调用与下载已验证，见[生图接入说明](workbench-images.md)。现已连接参数化外形、真实布局投影及可打印分件的有限几何执行器；详见[装配合同](workbench-assembly-design.md)。固件编译工具尚未接入该工作台；Pi仍没有通用shell、任意文件写入或审批工具。

运行数据位于忽略的 `workspace/workbench/`，新项目归档旧项目。中断执行在重启后标为错误；用户可向产品经理补充要求后重新决策。后续与原后台互接仍需授权查看相关接口并添加显式版本转换。

## 真实接入测试后的修复（2026-10-27）

- 产品经理模型只返回摘要和受校验的调度决策；后台将其封装为五通道协议，避免模型在工程通道中自行添加`process`等字段。
- 审查者可只返回受校验的意见列表，后台封装成`logic/review-finding`，始终标记建议性，不提供审批工具。
- 每个真实调用记录请求的provider与model ID。不能根据产品经理的文字摘要认定某角色已执行，应查询实际节点记录和`state.completedByRole`。
- 明确提供`state.itemIds`区分工程条目ID与调用ID。非法引用会给出缺失目标，不能用猜测缩写冒充引用。
- 产品经理格式错误最多发起两次独立修正调用；原错误节点保留。缺少结构所需的硬件或外观前置结果时阻塞并列明缺口。
- 用户可在执行中追加反馈，在下一轮决策生效；最新反馈置于显式指令及输入末尾，优先于旧决策摘要，不绕过认证、协议或依赖检查。
- 专家仅继承选中的工程依赖，不经产品经理节点递归带入所有无关历史，避免旧摘要干扰与输入膨胀。
- 预览按条目kind跨五通道识别硬件候选、图像请求，不依赖模型恰好把它们放在某一个通道。
- 几何坐标约定`xyz-mm-center-z-up/1`：世界原点为底面中心，X向右（宽）、Y向前（长）、Z向上（高）。dimensionsMm为XYZ尺寸，positionMm为世界坐标下该包络中心，特征点也采用同一世界坐标，不再额外叠加外包络中心。视图采用Z向上。历史包没有完整声明时应标记待核对，不能臆测为已经校验的CAD。
- 所有输出仍是提案；字面一致性、尺寸盒范围核对、意见列表有效，不等于真实CAD、碰撞、公差、电路、射频或固件测试通过。

## 缺口和调用可靠性

专家可返回精简的五类条目列表，由应用封装为版本化协议。硬件条目引用已有真实证据 ID，应用填入来源和版本；无证据的引用会被拒绝。完整记录保存在项目中，传给模型的资料摘要经过压缩，必要时仍可调用硬件工具读取。硬件库精确检索无结果时会标记宽松匹配，命中仅为待核实候选。

结构与软件的必要前置结果、必需硬件缺口和未完成的外观图在进入相应阶段前列明；相同错误反复出现时停止自动重试。用户可在登录后的工作台选择“带着这些缺口继续”并再次确认；决定和具体缺口随项目保存，后续结果继续标记未解决事项，新出现的缺口不会被自动豁免。生成图片的完成声明需要对应的实际工具产物；计划和待生成请求不算完成。

实际番茄钟复测及尚未解决的问题见 2026-10-28 复测记录（本地历史记录，未随轻量检查点上传）。

后续已经获得真实外观四图、五件有来源的硬件候选、四个STEP网格的结构布置和三张实际几何投影，见结构阶段验证（本地历史记录，未随轻量检查点上传）。后台会先将阶段缺口交回产品经理尝试诊断与修复；无来源的candidate仍算缺口，最新有效基线排除的备选不阻塞结构。轮廓投影必须消费已完成的结构布置，不能与首次结构任务同时启动。geometryItemId可直接引用已检查的几何条目，由后台补全geometryRef、尺寸与网格。产品经理使用当前结构快照与代码摘要，专家仍可获得完整依赖产物。

用户通过反馈授权采用原型估值后，专家可在设计结果中填入暂定值并保留`designAssumption`，不改写供应商资料或STEP尺寸。实际案例见番茄钟暂定参数落地（本地历史记录，未随轻量检查点上传）。输入过大时，所有角色均可通过只读`workbench_read_result`查询本次输入中的完整工程条目；结果索引不会删除原始数据。分类标签优先展示可用的最近修订，失败历史继续保留。

## 本地外部依赖（不随Git上传）

硬件数据目录用WORKBENCH_LIBRARY_ROOT设置，geometry Python用WORKBENCH_GEOMETRY_PYTHON设置。默认沿用开发机器相邻CAD目录，新机器需要明确配置，不会自动获得源数据库。可以用根目录npm run setup:cad安装已有锁定工具链，再令WORKBENCH_GEOMETRY_PYTHON指向本仓库.venv/bin/python；首次安装需要网络，安装过程没有在本次推送验收中重跑。密钥只在本机工作台设置页填写。浏览器UI回归需本机Chrome；默认夹具测试不需要真实模型API或硬件库，--history仅适用于本机已有历史快照。
