# DreamaticMake 开发与验收计划

日期：2026-10-18 · 对应方案：`docs/system-design.md`

## 1. 实施原则与范围

本文件记录初始实施计划，当前实现与验收状态见 `implementation-status.md`。后续在 DreamaticMake 独立实现，按模块迁移 Dreamatic 可复用能力，保留引用代码的许可证和来源。不修改 Dreamatic 原项目。

先用真实部件、CAD 和编译工具验证最小工程闭环，再扩展目录和设计自由度。工作量是开发人日估计，包含阶段内调试，需在 P0 后更新；不是已经承诺的交付日期。单人顺序推进约 42–62 人日，另留约 20% 集成缓冲；外部服务接入、工具链打包和实物返工可能增加时间。

## 2. 分阶段安排

| 阶段                   | 预计人日 | 工作内容                                                                                  | 可验收结果 / 完成条件                                                                            |
| ---------------------- | -------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| P0：技术验证与契约     | 3–5      | 锁定 Pi 1.3.0；验证旧版 SDK 差异；验证 build123d、PlatformIO 与隔离方式；选定一组真实部件 | Pi 流式会话/取消/恢复可用；最小外壳导出并回读 STEP/STL；目标板固件构建通过；接口与工具链决策记录 |
| P1：工作台与项目基础   | 5–7      | React/Node monorepo、Dreamatic 视觉、项目管理、Codex 风格聊天、设置、SSE 和存储           | 新建/切换/重开项目；设置原子保存且密钥不泄露；真实流式会话；前后端状态一致                       |
| P2：阶段引擎与用户确认 | 5–7      | 八阶段、六个确认门、版本/哈希、依赖失效、阶段预览框架、恢复与幂等                         | 不能越过未确认阶段；旧版本确认被拒绝；重启仍停留在等待确认；硬件变更准确标记下游失效             |
| P3：需求与硬件选型     | 6–9      | 澄清/意图卡、首批经核验部件、来源、BOM、兼容检查、接线与尺寸包络                          | 用户选择方案后生成一致的 BOM/引脚/几何契约；尺寸缺失会阻止精确建模确认；包含一组故意不兼容的反例 |
| P4：外观、结构与 CAD   | 10–15    | 外观候选、装配布局、壳体模板、参数化 CAD、3D 预览、几何与打印检查、六阶段确认闭环         | 用户确认后生成可重建源文件、STEP 与分件 STL；部件碰撞/开孔错误可被发现；预览与导出绑定同一版本   |
| P5：固件与交付闭环     | 7–10     | 固件状态机、引脚契约生成、构建和测试日志、交付清单与 ZIP                                  | 锁定依赖后可构建；接口变化触发重建；导出包可独立复现 CAD 和固件，且不含凭据                      |
| P6：桌面集成与实物验收 | 6–9      | Electron、工具链发现/安装诊断、故障恢复、实物打印/装配/烧录、文档                         | 首发桌面平台可运行；真实原型工作；发现的尺寸/装配/固件问题闭环修复并重新确认                     |

依赖顺序：P0 → P1 → P2 → P3 → P4 → P5 → P6。P4 完成时是「完整设计流程预览版」；P5 完成时是「软件工程闭环版」；P6 完成才是「经实物验证的原型版本」。

## 3. P0 首批具体任务

1. 初始化 monorepo、TypeScript 配置、基础脚本和忽略规则，添加许可证来源记录。
2. 安装精确版本 Pi 1.3.0 并提交锁文件；实现极小 SDK 适配器，验证事件订阅、工具、停止、steer/follow-up 和会话重开。
3. 对照 Dreamatic 0.85.1 使用点核对导出符号与会话配置差异，不直接搬迁大型 `extension.ts`。
4. 固定 CAD Python 环境，脚本生成带安装孔的上下壳，输出 STEP/STL/预览网格并验证单位、实体和尺寸。
5. 固定一组实际主控、显示和传感器的型号/修订版，收集可信尺寸与开源证据，建立样本目录。
6. 用同一引脚表构建最小固件，保存工具链版本和日志；验证目标框架、驱动及平台许可和分发条件。
7. 验证 CAD/编译进程取消、超时和目录/密钥访问边界，选定首发平台的执行隔离方案。
8. 提交项目、阶段、审批、部件、装配、产物和事件 Schema，更新后续工作量与风险记录。

P0 退出条件：Pi、CAD、固件、进程隔离四条路径均有真实验证证据；失败项说明替代方案和影响后再进入相关实现。

## 4. 关键验收用例

| 用例                               | 预期结果                                               |
| ---------------------------------- | ------------------------------------------------------ |
| 从一句模糊需求创建终端项目         | 分开形成需求与意图预览，分别等待用户确认               |
| 未确认硬件就请求生成最终 CAD       | 服务端拒绝依赖任务，说明需要确认的版本                 |
| 已核验部件与尺寸缺失部件混合选型   | 后者标记资料缺口，不生成虚构安装孔或精确配合           |
| 候选存在供电/逻辑电平/总线地址冲突 | 规则检查指出具体部件与原因，不能作为已通过方案         |
| 同时打开两个窗口确认不同版本       | 仅当前版本生效，过期请求收到冲突响应                   |
| 将主控更换为不同尺寸/引脚的型号    | 结构/CAD/固件等依赖失效，保留历史，重新验证            |
| 停止 CAD 或固件任务                | 工作进程结束，无残留写入，未完成产物不发布             |
| 断网重连、刷新、服务重启           | 事件可续接，阶段和审批可恢复，完成任务不重复执行       |
| 构建或 CAD 验证失败                | 展示真实诊断，有限次修复，失败时不显示成功             |
| 预览文件被替换或哈希不一致         | 阻止确认/交付并提示版本失效                            |
| 导出项目并在干净环境复现           | CAD 与固件按锁定版本重建，清单完整，秘密文件未导出     |
| 打印、装配、烧录样本终端           | 接口可达、部件可安装、壳体可闭合，产品关键功能通过测试 |

单元测试集中在审批、依赖传播、兼容规则、路径和秘密字段边界；集成测试覆盖 SDK、CAD、编译和恢复；浏览器测试覆盖确认与预览流程；实物测试记录照片、测量和功能结果。模拟工具可用于前期 UI 开发，但模拟产物不得计入工程闭环验收。

## 5. 首版边界与后续扩展

首版包含受控目录选型、六次确认、真实参数化 CAD 和固件构建、项目恢复、设置及导出。优先验证一种主控/框架组合和常见螺丝固定壳体。

后续逐步扩展：更多主控和目录来源、用户自建部件库、任意 STEP 导入与尺寸辅助识别、更自由的工业造型、切片适配、串口调试、复杂供电、经验证的多会话协作、Windows/Linux 工具链打包。

重点风险：资料缺尺寸、概念图与实体约束偏离、CAD 布尔运算失败、板卡修订不一致、编译环境下载和版本漂移、桌面打包体积、实际打印公差。分别通过来源门槛、共享几何契约、受控模板、精确型号、版本锁定、P0 打包验证与试片/实物测试降低风险。
