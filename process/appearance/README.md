# 外观设计与效果图生成

## 任务与来源

把需求和功能转化为可查看的产品外观效果图及说明。必需上游：`requirements`。案例读取 `doc/requirements/`、`doc/appearance/` 的登记资料，附已有项目摘要与明确的外观约束。完整产品设计默认执行效果图生成；仅当用户明确只要文字讨论、工程建模或跳过外观时，才按其范围省略。

## 给 Agent 的上下文

按“目标用户/场景 → 功能与交互区域 → 形态/色彩/材质意向 → 必须保留的活动空间 → 参考图来源”组织。对机械臂列明底座稳定性、关节活动、夹爪开口、控制与供电区域；不可用渲染图证明安装尺寸成立。

图片附视角、用途、来源和可用状态。默认提供一张完整产品的三分之四视角主效果图，以及覆盖正视、侧视、背面的辅助视图；可以合成一张多视图板。按产品需要补充夹爪打开/闭合、接口、操作区或装配关系特写。这些是执行要求，不是模型枚举限制。已有几何可作为参考，但初始概念效果图不以选型或 CAD 完成为前提。

效果图表达整体比例、形态、配色、材料、表面处理、灯光与使用情境。CAD 线框、尺寸图、STL 浏览截图及简单投影图仍作为工程检查附件保存，不能单独替代产品效果图；基于真实 CAD 的材质与灯光渲染可以作为深化效果图，并注明来源。

## 执行 prompt

应用公共执行规则，给出能继续落地的外观方向：

1. 从需求提取产品类型、整体比例、功能区域、活动部件、配色/材质及必须露出或隐藏的接口。沿用用户已选形态；未确认细节标为建议。机械臂必须明确三个定位轴和双指夹爪，不能为了造型增加关节或改变夹爪结构。
2. 编写生成提示词：说明完整产品、视角、背景、材料、配色、功能区域、活动姿态、比例及需要避免的结构错误。将同一产品的多视图作为一组，统一底座、关节数量、接口位置和配色。概念尺寸均为设计假设，不要求生成工具伪造精确尺寸标注。
3. 由宿主实际调用可用的图像生成工具（例如 ImageGen，并遵循该工具/技能的使用约定），取得真实图片；有参考图或现成 CAD 时，先读取参考图，再用图像编辑/参考图生成保持结构一致。不能只写提示词或返回一个未来的文件路径便宣称生成完成。宿主没有可用图像工具时，保留提示词与缺口并明确标记“效果图未生成”，继续可独立完成的工作。
4. 查看实际输出，核对主视图与辅助视图的轮廓、数量、接口、关节、开合状态和活动空间。若结构与需求不符，修改提示词或基于当前图继续编辑，再检查；不要将明显矛盾的图片直接交给布局/CAD阶段。
5. 将真实图片保存到 `doc/appearance/`，按实际字节计算哈希，登记文档索引和图像元数据。在阶段 README 和项目入口展示或链接主效果图；向用户交付时直接展示可用的图片。用已有元数据文件保留提示词与来源，不默认另建提示词 Markdown。
6. 选型、布局和 CAD 深化后，对照最初效果图核对外廓、比例、关节和接口。如果发生可见变化，以当前 CAD 预览为参考修订效果图，或用真实 CAD 渲染器生成材质/灯光效果图；同一 `appearance` 阶段保存新版本，保留旧版本及来源，并更新当前展示入口。效果图不能反向覆盖工程尺寸，也不能作为配合、强度或制造成功的证据。

## 文件交付与元数据

推荐文件为 `concept-board-v0.1.png`（概念效果图）、`cad-render-v0.2.png`（深化后效果图，确已执行时才建立）及 `assets-v0.1.json`（或项目已有的图像元数据文件）。文件名可按项目调整，不预建空图片。

文件任务的元数据至少记录：图像 ID、相对路径、媒体类型、SHA-256、视角/用途、生成方式与实际工具、提示词、参考图片路径及哈希、相关需求/设计基线、生成时间，以及查看后的检查结论和仍存在的差异。未使用参考图时列表为空；工具未返回模型名或参数时记未知，不猜测。概念生成、参考 CAD 的生成图与真实 CAD 渲染分别标注，避免把生成细节当作真实结构。此记录是宿主文件约定，不给 `AppearanceImage` 增加未定义字段。

## 输出与检查

产物：`AppearanceOutput(images, design_notes)`；每张 `AppearanceImage` 有唯一 `image_id`、`AssetRef`、`view` 和 `caption`，媒体类型必须为 `image/*`。图像字节由宿主接入的生成/上传能力提供，流程本身不生成图片。

文件任务：图片、元数据和说明存入 `doc/appearance/` 并登记 `doc/index.json`，不改动位姿或元件几何。说明图中的关键区域、概念尺寸与尚未验证的内容。

完成本阶段前，检查图片确实存在且可打开、哈希与实际字节一致、主效果图和辅助视角齐全、产品结构与需求一致、来源/提示词/检查记录完整、索引与展示入口有效。`submit` 仅校验引用和数据契约，不读取图像字节，也不验证图中尺寸。缺少真实图片时不能编造可用路径和哈希，也不能以工程预览代替后标记效果图已完成。未生成图片的文字讨论仅作为文件草稿，不提交要求至少一张图的 `AppearanceOutput`。

## 接口与公共约定

本目录 `__init__.py` 导出该阶段 Input/Output/Request/Process，依赖与上下文键由 Process.spec 定义。运行 `python -m process schema appearance` 查看实际 schema。信息读取、版本、Agent 调用与写回边界统一见 [CONTEXT.md](../CONTEXT.md)。
