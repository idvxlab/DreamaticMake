# 案例设计与文档精简规则

后续在 `examples/` 创建或继续设计时，按本文组织文件。工程目录格式继续参照 [project_1](../examples/project_1/README.md)；保留结构，不照搬其说明文字，也不复制 `project_2` 的全部追溯附件。

## 必要文件与权威来源

| 内容 | 保存位置 | 保留原因 |
| --- | --- | --- |
| 项目入口、实例来源、文档索引 | `project.json`、`element/index.json`、`doc/index.json` | 原生加载与查找入口；按当前 schema 保留 |
| 元件、接口、几何、材料与资产引用 | `element/<custom>/manifest.json` + 原生定义；库件为精确引用 | 可复用、可解析的工程定义；同型实例共用 |
| 布局、网络、运动/固定关系 | 清单指定的三个 `design/*.json` | 唯一可执行项目设计，不再维护 Markdown 坐标/网络副本 |
| 用户目标、功能、验收、决定与关键假设 | `doc/requirements/README.md` | 下游设计依据；文件任务可合在一份，保留稳定需求/功能 ID 和来源定位 |
| 阶段独有的设计理由和操作说明 | 已执行阶段的 `doc/<stage>/README.md` | 只写 JSON/资产无法表达的取舍、未知项、装配/打印操作及证据链接 |
| CAD 源、STEP/STL、图片、BOM、校验结果 | 所属元件包或对应阶段附件 | 实际交付与复现证据，不能因精简 Markdown 而删除 |

项目根 `README.md` 只提供当前方案、重要约束/未完成项和交付入口。阶段说明采用“结论 → 关键取舍/假设 → 验证与附件 → 下一项阻塞”的短结构；没有独有内容的阶段不创建 README，也不创建占位成果。简单项目可以只需根说明和需求说明；九阶段都有独有成果时通常为 10 份常规 Markdown，不是硬性配额。

需求文件的合并仅适用于文件任务。产物 API 仍需分别提供 `requirements` 与 `functions` 角色，不能以精简磁盘文件为由省略必需产物或修改 schema。

## 默认不再新增的 Markdown

- `doc/README.md`、`design/README.md`、`element/README.md` 等重复导航：由根 README 和 JSON 索引承担导航，通用格式说明留在 engine/element/process 文档。
- 每个打印件一份“STEP 在哪里、单位 mm、尚未试打”的模板 README：资产入口、单位与版本已有原生字段；试打状态由阶段说明统一记录。
- 单独的 `source.md`、`decisions.md`、`functions.md`：普通案例把必要内容并入需求说明。来源很多、行为复杂或需要独立评审时才拆分，不能丢掉用户原话与设计推导的区别。
- 单独的功耗预算 Markdown：简单预算放选型说明；复杂、需计算复现时保存计算源/结构化结果并链接。电源路径、假设和测试计划必须保留。
- 图片提示词 Markdown、每轮计划/总结/交接/验证摘要：提示词可存已有图像元数据，执行过程放忽略的 `workspace/`；实际校验记录保留结构化结果。确有复现实验需要时才另存，不同时维护多份相同摘要。
- 全量复制 JSON 的表格、每轮生成新的 Markdown 版本、每阶段重复项目背景/流程 API/免责声明：链接权威源，正文只维护当前结论。

元件 README 仅在存在原生定义无法合适表达的独有使用、校准、加工或复现说明时保留；不能只为减少数量把必要注意事项删掉，也不要无故修改已固定元件版本。

## 本次设计的审计与后续收敛

2026-11-06 审计：`project_1` 有 11 份 Markdown；`project_2` 有 37 份。后者的原生工程、CAD、BOM、来源和检查记录有用，Markdown 的主要问题是分散和重复。

| project_2 文档 | 判断 | 下次维护或迁移方式 |
| --- | --- | --- |
| 根 README + 9 个阶段 README | 保留有效结论，压缩重复背景 | 根目录只导航；各阶段只写本阶段独有信息 |
| 需求的 source/functions/decisions 三份附文 | 内容必要，分成三个文件不是必需 | 合并到需求说明的来源、功能、决定与待定章节 |
| hardware_selection/power-budget.md | 预算及假设必要，独立文件可选 | 简单预算合入选型说明，保留计算和来源 |
| appearance/prompt-v0.1.md | 生成参数有复现价值，单独 Markdown 可选 | 新图提示词写图像元数据；保留已有历史引用 |
| 12 个打印件 README | 重复资产路径和通用状态，无需逐件生成 | 新打印件不创建；独有打印注意事项归打印阶段 |
| 7 个电子元件 README | 含接线、极性及模型边界，内容有价值 | 先核对原生定义/选型说明是否已完整表达，再决定合并 |
| doc/design/element 三份目录级 README | 导航与格式重复 | 后续合入根入口和通用契约，不再新增 |

本次先建立后续执行规则，现有案例文件保持原路径。`project_1` 继续作为格式样例；`project_2` 的旧文件已被上游快照、来源哈希、资产元数据或版本记录引用，不能直接删除再覆盖历史哈希。按上表完成信息合并后，理论上可从 37 份收敛至约 10 份；复杂元件/预算可保留少量独立说明。

迁移已有案例时，先检查 Markdown 链接、`doc/index.json`、源哈希、复现脚本和版本 pin 的引用；只对当前版本改入口，历史快照仍指向原始字节。不得为了精简把未执行检查写成通过，或删掉未接端子、充电/极性、装配顺序、公差和测试边界。迁移后运行原生项目加载与失效链接检查；涉及工程变更时再运行相应检查。
